# H1: сигнал энтропии cross-attention при генерации с RTC

**Гипотеза H1.** Сигнал $h^*$, предложенный для синхронного режима [15], остаётся информативным при генерации с guidance RTC.

## Что проверяется

Сигнал $h^*$ строится из энтропии $\mathcal{E}_j$ cross-attention токена действия $j$ к токенам наблюдения. Он информативен, если действия с большей энтропией имеют большую ошибку. H1 проверяется офлайн на демонстрациях LIBERO.

**Критерий.** Для чанков, сгенерированных с RTC, вне замороженной зоны $[0, d)$: коэффициент Спирмена между $\mathcal{E}_j$ и ошибкой действия не менее 0.15, нижняя граница 95% доверительного интервала больше 0.

**Частный коэффициент.** И энтропия, и ошибка растут с индексом $j$, поэтому обычный коэффициент Спирмена положителен даже при неинформативном сигнале. По умолчанию используется частный коэффициент: ранги центрируются внутри каждого $j$, то есть сравниваются действия на одной позиции в чанке. Обычный коэффициент тоже выводится; `--criterion raw` использует его в критерии.

**Замороженная зона исключена:** там guidance притягивает действия к предыдущему чанку, и ошибка определяется им, а не уверенностью текущей генерации.

## Протокол

1. Политика `lerobot/pi05_libero_finetuned` (π0.5, $H = 50$, 10 шагов денойзинга), датасет `HuggingFaceVLA/libero`.
2. В каждом эпизоде кадры $t_k = t_0 + k s$, $t_0$ случаен в $[0, s)$.
3. На каждом кадре генерируются два чанка из одного наблюдения и одного шума: без guidance и с RTC. RTC привязывает чанк к остатку предыдущего RTC-чанка, сдвинутому на $s$: первые $d$ действий заморожены, мягкая маска EXP до $H - s$. Первый кадр эпизода только запускает цепочку.
4. Для каждого действия сохраняются энтропия на каждом шаге денойзинга и ошибка: MSE относительно демонстрации, каждая размерность делится на std датасета. Действия за концом эпизода исключаются.
5. Доверительные интервалы: бутстрэп по эпизодам.

## Guidance

`RTCProcessor` в LeRobot вычисляет скорость $v_t$ до включения градиента по $x_t$, поэтому из guidance выпадает якобиан денойзера (в статье RTC [7] — vector-Jacobian product). Режим `--guidance exact` (по умолчанию) восстанавливает VJP и исключает из ошибки размерности паддинга. Режим `--guidance lerobot` — реализация LeRobot без изменений.

## Установка

Нужны Linux, NVIDIA GPU (π0.5 в bf16; рекомендуется от 16 ГБ) с драйвером не ниже 570 (LeRobot ставит torch с CUDA 12.8), ffmpeg и [uv](https://docs.astral.sh/uv/).

```bash
sudo apt install ffmpeg
git clone https://github.com/DanElis/confidence-budget.git
cd confidence-budget/experiments/h1
uv sync
uv run hf auth login
```

`uv sync` ставит Python 3.12 и LeRobot на проверенном коммите (`pyproject.toml`). Токенизатор `google/paligemma-3b-pt-224` закрыт: до запуска примите лицензию на его странице на Hugging Face.

Проверка без загрузки модели (маленькая случайная π0.5 на CPU, около 30 с):

```bash
uv run pytest -q
```

## Запуск

Пробный прогон:

```bash
uv run python scripts/collect_h1.py --episodes 2 --max-chunks 2 --out runs/smoke.npz
uv run python scripts/analyze_h1.py runs/smoke.npz --n-boot 100
```

Основной прогон:

```bash
uv run python scripts/collect_h1.py --episodes 100 --out runs/h1_exact.npz
uv run python scripts/analyze_h1.py runs/h1_exact.npz
```

Если метаданные датасета не совпадают с файлами данных (так у `HuggingFaceVLA/libero`), сбор сам переходит на загрузку всего датасета, около 35 ГБ; `--full-dataset` делает это сразу. Сбор сохраняет файл каждые 10 эпизодов (`--save-every`). Результат анализа — в `runs/h1_exact/`: `summary.md`, `summary.json`, `h1_report.png`.

Проверки устойчивости:

| Что меняется | Команда |
|---|---|
| guidance LeRobot | `collect_h1.py --guidance lerobot --out runs/h1_lerobot.npz` |

## Конфликт старого чанка и наблюдения

На плавных демонстрациях LIBERO новый чанк почти совпадает со старым, и guidance почти не меняет генерацию. Чтобы проверить H1 при заметном вмешательстве, конфликт создаётся искусственно:

- `--prev-shift σ` — остаток старого чанка сдвигается на σ std нормированных действий (знак случаен по размерности, захват не сдвигается без `--shift-gripper`);
- `--prev-source stale --stale-frames L` — старый чанк спланирован по наблюдению, устаревшему на L кадров.

Вся серия (σ = 0.25, 0.5, 1, 2; L = 25, 50, 100; оба режима guidance), около 3–4 ч на A100:

```bash
bash scripts/run_sweep.sh
```

Готовые запуски пропускаются, поэтому скрипт можно перезапустить после обрыва. Прогресс — в `runs/sweep.log`, сводная таблица — в `runs/sweep.md` (`scripts/sweep_table.py`).

## Интерпретация

| Результат | Вывод |
|---|---|
| RTC: критерий выполнен | H1 подтверждена |
| RTC и без guidance: коэффициент низкий | сигнал не работает и без guidance; H1 не проверяема на этих данных |
| без guidance: высокий; RTC: низкий, CI разности ниже 0 | guidance разрушает сигнал; H1 опровергнута |

Контрольные величины в `summary.md`:

- **RMSE в замороженной зоне.** У RTC должна быть много меньше, чем без guidance; иначе guidance не работает.
- **Доля чанков с плато.** Около 0 или 1 означает, что порог $\eta = 0.95$ из [15] не подходит для LIBERO; сравните его с квантилями нормированной энтропии и задайте `--plateau-eta`.
- **Ошибка после $h^*$ / до $h^*$.** Больше 1 — $h^*$ отделяет точные действия от неточных.

## Ограничения

- Офлайн: наблюдения берутся из демонстраций, предсказанные действия не исполняются. Ошибка — отклонение от демонстрации, а не неуспех задачи.
- Политика дообучена на этих же демонстрациях, поэтому ошибки занижены.
- Демонстрация — одна из допустимых траекторий; мультимодальность увеличивает ошибку независимо от уверенности.
- Пороги плато взяты из [15] для другой конфигурации камер и токенов.
