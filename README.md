## 1. Мотивация

Современные VLA-модели, такие как $\pi_0$ [3], $\pi_{0.5}$ [4] и GR00T [5], управляют роботом через чанкинг действий: по одному наблюдению политика предсказывает последовательность из $H$ будущих действий и до следующего перепланирования исполняет её префикс, как правило, короче всего чанка [1, 2, 7]. Чанкинг даёт временную согласованность, но порождает компромисс: длинное исполнение без перепланирования снижает реактивность, короткое ведёт к перескокам между стратегиями на стыках чанков [6, 7].

Вторая проблема — задержка инференса. Крупные VLA не успевают выдать чанк за один период управления: у $\pi_0$ с её 3 млрд параметров только заполнение кэша занимает 46 мс на RTX 4090 при периоде управления 20 мс [7]. Поэтому на реальном роботе инференс запускают асинхронно, пока исполняется предыдущий чанк.

По этим двум проблемам сложились две независимые линии работ.

- **Чанкинг реального времени** (RTC [7], training-time RTC [8], Legato [9]) обеспечивает гладкую стыковку чанков при задержке, но шаг перепланирования и форма привязки к прошлому чанку задаются заранее и не меняются по ходу задачи.
- **Адаптивный чанкинг** (AAC [13], AutoHorizon [14], метод на cross-attention [15]) выбирает длину исполняемого префикса по уверенности самой политики, но рассматривает синхронный режим: задержка не моделируется, механизма стыковки нет.

**Открытые проблемы.**

1. Методы адаптивного горизонта не учитывают, что часть чанка устаревает за время инференса, и не определяют, когда запускать следующий расчёт.
2. В методах реального времени привязка нового чанка к старому не зависит от того, насколько старый план был обоснован.
3. Наилучшие значения шага перепланирования и длины привязки к прежнему чанку различаются между задачами и между фазами одной задачи [7, 9, 13–15].

**Научная значимость:** предложена постановка задачи адаптивного чанкинга при задержке инференса: шаг перепланирования и длина привязки к предыдущему чанку ограничены надёжным горизонтом политики за вычетом задержки. Адаптивный горизонт [13–15] и RTC [7] являются её частными случаями.

**Практическая значимость:** в реальной среде условия меняются по ходу задачи, а частота перепланирования и привязка к прежнему плану задаются заранее и остаются постоянными. Предлагаемый метод выбирает их на каждом чанке и применяется к уже обученной политике без изменения её весов.

## 2. Постановка задачи исследования

**Обозначения.** Политика $\pi(\mathbf{A}_t \mid \mathbf{o}_t)$ выдаёт чанк $\mathbf{A}_t = [\mathbf{a}_t, \dots, \mathbf{a}_{t+H-1}]$ из $H$ действий, где $H$ — горизонт предсказания (длина чанка), заданный при обучении. Пусть $\Delta t$ — период управления, $\delta$ — время инференса, $d = \lfloor \delta / \Delta t \rfloor$ — задержка в шагах [7].

**Асинхронное исполнение.** Инференс $k$ стартует в момент $t_k$ по наблюдению $\mathbf{o}_{t_k}$; чанк доступен в момент $t_k + d$. Шаг перепланирования $s_k = t_{k+1} - t_k$ удовлетворяет ограничению реального времени

$$d \le s_k \le H - d.$$

Из чанка $k$ исполняются действия с индексами $[d,\; s_k + d)$.

**Стыковка.** Чанк $k{+}1$ генерируется с привязкой к остатку чанка $k$ по маске $\mathbf{W} \in [0,1]^H$, веса которой принимают вещественные значения от 0 до 1:

$$W_i = \begin{cases} 1, & i < d, \\ w(i), & d \le i < d + r_{k+1}, \\ 0, & i \ge d + r_{k+1}, \end{cases} \qquad i = 0, \dots, H - 1,$$

где $W_i$ — вес привязки $i$-го действия нового чанка к соответствующему действию предыдущего, $r_{k+1}$ — длина спада, а $w(i)$ убывает от 1 до 0 по тому же закону, что в RTC [7]: $w(i) = c_i \dfrac{e^{c_i} - 1}{e - 1}$, $c_i = \dfrac{d + r_{k+1} - i}{r_{k+1} + 1}$. В RTC $r = H - s - d$ и $s$ постоянны.

**Сигнал уверенности.** По внутренним состояниям политики при генерации чанка $k$ вычисляется надёжный горизонт $h^*_k \in \{1, \dots, H\}$: число действий от момента наблюдения, которые политика считает обоснованными [13–15].

**Ограничение бюджета.** Замороженный префикс чанка $k{+}1$ соответствует индексам $[s_k,\; s_k + d)$ чанка $k$, спад — индексам $[s_k + d,\; s_k + d + r_{k+1})$. Требование, чтобы привязка опиралась только на надёжные действия:

$$s_k + r_{k+1} \le h^*_k - d, \qquad s_k \ge d, \quad r_{k+1} \ge r_{\min}.$$

Следствие: при $h^*_k < 2d + r_{\min}$ допустимых пар $(s, r)$ нет.

**Задача.** Найти стратегию исполнения $\varphi: (h^*_k, d) \mapsto (s_k, r_{k+1})$, которая

$$\max_{\varphi}\; \mathbb{E}\big[R(\tau)\big] \quad \text{при} \quad \mathbb{E}\big[S(\tau)\big] \le S_0, \quad d \le s_k \le H - d,$$

где $\tau$ — траектория при исполнении политики $\pi$ со стратегией $\varphi$, $R$ — успешность, $S$ — мера негладкости траектории (чем больше значение, тем менее плавное движение; используется NSPARC [9, 24], раздел 5), $S_0$ — её уровень для базового RTC.

**Предлагаемое семейство стратегий.** Пусть $\rho_k = h^*_k - 2d - r_{\min}$ — свободный остаток бюджета, $\lambda_k \in [0, 1]$ — доля остатка, идущая в шаг перепланирования:

$$s_k = d + \lfloor \lambda_k \rho_k \rfloor, \qquad r_{k+1} = r_{\min} + \lceil (1 - \lambda_k) \rho_k \rceil \qquad (\rho_k \ge 0),$$

иначе $s_k = d$, $r_{k+1} = r_{\min}$. Частные случаи при постоянном $\lambda_k$: $\lambda = 0$ — адаптивная маска; $\lambda = 1$ — адаптивный горизонт; $h^*_k \equiv H$ — RTC с фиксированным шагом, так как тогда $s$ постоянен и $r = H - s - d$. Неравенство бюджета задаёт сумму $s + r$, но не способ её деления, поэтому способ выбора $\lambda_k$ вынесен в гипотезу H2.

**Гипотезы.**

- **H1.** Сигнал $h^*$, предложенный для синхронного режима, остаётся информативным при генерации с guidance.
- **H2.** Долю $\lambda_k$ можно выбирать автоматически без потери качества относительно ручного подбора. Сравниваются три способа:
    1. сетка: постоянное значение, подобранное перебором;
    2. энтропия: значение вычисляется для каждого чанка по тому, как быстро растёт энтропия cross-attention от первых действий чанка к последним;
    3. обучение: значение предсказывает небольшой модуль поверх замороженной политики, обученный в симуляции.

  Ожидается, что способы 2 и 3 не уступают лучшему значению из сетки на каждой задаче и превосходят единое постоянное $\lambda$ в среднем по задачам.

## 3. Обзор известных подходов

**3.1. Фиксированный горизонт.** ACT [1] ввёл чанкинг и усреднение перекрывающихся предсказаний (temporal ensembling). Diffusion Policy [2] и VLA-модели [3–5] исполняют фиксированный префикс чанка. Достоинство — простота. Недостаток — горизонт подбирается вручную под задачу. BID [6] формализовал компромисс «согласованность — реактивность» и выбирает лучший чанк из пакета сэмплов, что требует кратно больше вычислений.

**3.2. Асинхронное исполнение.** Наивная асинхронная схема даёт скачок на стыке чанков. RTC [7] ставит стыковку как задачу дорисовки: первые $d$ действий замораживаются, остальные генерируются с мягкой маской. Достоинство — работает на готовой модели. Недостатки — обратный проход на каждом шаге денойзинга (задержка модели выросла с 76 до 97 мс) и фиксированное расписание. Training-time RTC [8] переносит условие на префикс в обучение: накладных расходов нет, при больших задержках результат лучше, но нужно дообучение, а маска бинарная. Legato [9] обучает политику под расписание с параметрами $(d, r)$ и подаёт его на вход; на пяти реальных задачах время выполнения и гладкость улучшаются примерно на 10% относительно RTC. Недостатки — дообучение, зашитое число шагов денойзинга и фиксированное расписание при развёртывании ($s = H/2$). Смежные работы: корректирующая голова A2C2 [10], ускорение реакции в FASTER [12], варианты мягкой маски и guidance [18, 19], маскирование чанков в REMAC [20]. Сравнительное исследование [11] показывает, что единого лидера нет, а методы на префиксе деградируют при росте доли префикса в чанке.

**3.3. Адаптивный горизонт.** SGAC [16] обновляет чанк выборочно по сходству старого и нового действия. AAC [13] оценивает энтропию действий по 20 сэмплам и обрезает чанк в точке её наибольшего роста; цена — около 20 мс на вызов. AutoHorizon [14] использует self-attention между токенами действий и не уступает лучшему подобранному фиксированному горизонту. Метод [15] использует энтропию cross-attention от действий к наблюдению: её выход на плато связан с ростом ошибки; надбавка менее 7 мс. VLA-Corrector [17] перепланирует по событию. Общий недостаток: синхронный режим, без задержки и стыковки.

## 4. Описание базового решения

За основу берутся два компонента: RTC [7] как механизм исполнения и энтропия cross-attention [15] как сигнал уверенности.

**4.1. RTC.** Flow-политика интегрирует поле скоростей $\mathbf{v}$ от шума ($\tau = 0$) к действиям ($\tau = 1$). RTC добавляет на каждом шаге поправку, тянущую оценку итогового чанка к остатку предыдущего $\mathbf{Y}$:

$$\mathbf{v}_{\Pi\text{GDM}} = \mathbf{v} + \min\!\Big(\beta,\; \frac{1-\tau}{\tau\, r_\tau^2}\Big)\, \big(\mathbf{Y} - \widehat{\mathbf{A}^1}\big)^{\!\top} \mathrm{diag}(\mathbf{W})\, \frac{\partial \widehat{\mathbf{A}^1}}{\partial \mathbf{A}^\tau},$$

$$\widehat{\mathbf{A}^1} = \mathbf{A}^\tau + (1-\tau)\,\mathbf{v}(\mathbf{A}^\tau, \mathbf{o}, \tau), \qquad r_\tau^2 = \frac{(1-\tau)^2}{\tau^2 + (1-\tau)^2}.$$

Мягкая маска:

$$W_i = \begin{cases} 1, & i < d \\ c_i\, \dfrac{e^{c_i} - 1}{e - 1}, & d \le i < H - s \\ 0, & i \ge H - s \end{cases} \qquad c_i = \frac{H - s - i}{H - s - d + 1}.$$

Фоновый поток ждёт, пока исполнится $s_{\min}$ действий, запускает инференс с оценкой $d$ как максимума последних измеренных задержек и подменяет чанк по готовности.

**4.2. Сигнал уверенности [15].** Для токена действия $j$ веса внимания к $N$ токенам наблюдения суммируются по слоям и нормируются в распределение $p_{i,j}$. Энтропия:

$$\mathcal{E}_j = -\sum_{i=1}^{N} p_{i,j} \log p_{i,j}, \qquad 0 \le \mathcal{E}_j \le \log N.$$

После сглаживания окном $k$ ищется первое окно, где энтропия высока и стабильна:

$$\mathcal{C} = \Big\{ j : \min_{0 \le n < k} \bar{\mathcal{E}}_{j+n} \ge \eta \log N,\;\; \Big| \tfrac{1}{k} \textstyle\sum_{n=0}^{k-1} \Delta \bar{\mathcal{E}}_{j+n} \Big| < \tau_{\mathcal{E}} \Big\},$$

$$h^* = \min(\mathcal{C}) + k, \quad \text{если } \mathcal{C} \ne \varnothing; \qquad h^* = H \text{ иначе}.$$

Авторы используют $k = 5$, $\tau_{\mathcal{E}} = 0.01$, $\eta = 0.95$.

## 5. Метрики

| Метрика | Что измеряет | Целевое значение |
|---|---|---|
| Success rate, % | доля успешных эпизодов | не менее +2 п.п. к базовому RTC |
| NSPARC [9, 24] | гладкость траектории | не хуже, чем у базового RTC |
| Signal–error correlation (H1) | пригодность сигнала под guidance | коэффициент Спирмена не менее 0.15 |

**Протокол.** Метрики оцениваются в симуляции на стандартных бенчмарках манипуляции [21–23] и на реальном роботе; результаты усредняются по нескольким запускам.

**Критерий успеха работы.** Подтверждена H1, и цель по success rate достигнута при соблюдении ограничения по гладкости.
