# Запуски только на сервере пользователя

Локальная машина (Windows) — только для чтения и правки кода. GPU нет, доступа к серверу по SSH у Claude нет.

## Не делать локально
- Не запускать скрипты экспериментов, `pytest`, `uv sync`/`uv run`, `pip install`, `nvidia-smi`.
- Не клонировать внешние репозитории и не скачивать чекпоинты/данные в рабочую копию.
- Не пытаться подключиться к серверу (`ssh`, `scp`).

Разрешено: читать и править файлы, `git` (status/diff/log/commit/push), читать внешний код и документацию через веб (GitHub, API бакетов) — только чтение.

## Как работать
1. Написать код и скрипты так, чтобы они запускались на сервере одной командой. Установка окружения и загрузки — отдельным скриптом (`setup.sh`), идемпотентным.
2. Проверить код без запуска: перечитать, сверить с API внешнего кода по исходникам.
3. Закоммитить и запушить (сообщения на английском), чтобы на сервере был свежий код.
4. Дать пользователю готовые команды для сервера, по одной в блоке `bash`, в порядке выполнения:
   - `cd ~/work/cv/confidence-budget && git pull && git log -1 --oneline`
   - `nvidia-smi` перед запуском на GPU (сервер общий);
   - сначала короткая проверка (малый размер, засечь время и память), потом полный прогон в `tmux`.
5. Попросить прислать вывод (лог, CSV, таблицу) и анализировать его по присланному. Результаты не выдумывать и не предсказывать.

## Сервер
- A100 80 GB, общий. Пользователь `eliseevds`, репозиторий `~/work/cv/confidence-budget`.
- Долгие запуски — в `tmux`. Логи `lib.sh` в UTC (MSK − 3).
